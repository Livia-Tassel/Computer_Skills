# 经典无损压缩算法
## 1.1 熵编码机制
熵编码（Entropy Coding）的核心思想源自克劳德·香农的信息论：一个符号的信息量与其出现概率的负对数成正比。压缩的本质，即是用较短的比特序列表示高频符号，用较长的比特序列表示低频符号，从而使平均码长逼近信源的熵。

### 1.1.1 霍夫曼编码（Huffman Coding）
霍夫曼编码属于变长编码（VLC）的一种，其核心是一个自底向上的二叉树生成算法：

1. **频率统计**：统计输入中每个符号（Symbol）出现的频率。  
2. **节点生成**：将每个符号视为一个叶子节点，其权重为该符号的频率。  
3. **树的构建**：在所有节点中选择权重最小的两个节点，将它们合并为一个新的父节点，父节点的权重为两个子节点权重之和。  
4. **迭代向上**：重复上述步骤，直到所有节点合并为一棵根树。  
5. **编码分配**：从根节点出发，向左走标记为 0，向右走标记为 1，到达叶子节点的路径即为该符号的二进制编码。

霍夫曼编码的一个关键是利用 “前缀性质”，即任何一个字符的编码都不是另一个字符编码的前缀，保证了无歧义解码。

### 1.1.2 算术编码（Arithmetic Coding）
算术编码将整个消息映射为区间 $[0, 1)$ 内的一个小数，其根据符号的累积概率将当前区间划分为更小的子区间。

1. **初始状态**：将当前区间设定为 $[0, 1)$。
2. **区间划分**：根据输入符号的概率分布，将当前区间划分为若干个子区间。
    - 概率高的符号拥有较宽的子区间。
    - 概率低的符号拥有较窄的子区间。
3. **区间更新**：读入一个符号后，将当前区间更新为该符号对应的子区间。
4. **迭代收缩**：重复上述过程，直到消息结束。随着消息变长，区间会变得越来越窄。

理论上可以达到香农熵的极限，通常比霍夫曼编码更高效，特别是在处理概率分布极端的符号时。

> **区间编码 (Range Coding)**：
  区间编码是算术编码的一个变种。在原理上，两者是等价的，都基于概率将消息映射到区间上。关键区别在于归一化，区间编码在字节级别进行归一化操作。

## 1.2 字典与序列压缩
熵编码利用的是符号频率的非均匀性，字典编码则利用了字符串的重复性。

### 1.2.1 行程编码（RLE）
行程编码将重复的序列替换为 “计数 + 值” 的对。

* **机制**：字符串 AAABBBBBCCCC 被编码为 3A5B4C。  
* **范围**：对于文本或自然图像，RLE 效果极差，但在二值图像、简单的计算机图形以及稀疏矩阵的存储中，RLE 极其高效。

### 1.2.2 LZ77：滑动窗口
LZ77 引入了 “滑动窗口” 的概念。编码器维护一个缓冲区，在处理当前数据流时，它会向前查找是否存在与当前待编码序列相同的字符串。

* 如果存在匹配，编码器输出一个三元组：(distance, length, next\_char)。  
  * distance：匹配字符串在缓冲区中距离当前位置的偏移量。  
  * length：匹配的长度。  
  * next\_char：匹配结束后紧跟的下一个字符。  

> **DEFLATE**：  
  至今最流行的压缩格式 DEFLATE（用于 ZIP, GZIP, PNG）就是 LZ77 与霍夫曼编码的结合体。

### 1.2.3 LZ78 与 LZW：显式字典
动态字典机制：从一个包含所有基础字符（如 ASCII 码）的初始字典开始。

1. 读取输入字符，与当前缓冲区组成字符串。  
2. 如果该字符串在字典中，则读取下一个字符。  
3. 如果不在字典中，则将该字符串添加到字典，并输出前一个字符串在字典中的索引。  

## 1.3 基于上下文建模
此类算法通过分析一个符号出现前的上下文来预测当前符号出现的概率，然后将这些概率信息传给熵编码器。

### 1.3.1 PPM：部分匹配预测
- **原理**：自适应统计压缩方法。它用当前符号前的 k 个符号来预测下一个符号的概率分布。如果 k 阶上下文未曾出现过，则算法会降低阶数（k-1），直到0阶。

### 1.3.2 BWT：块排序变换
- **原理**：BWT 通过对输入信息块的所有循环移位进行字典序排序，然后取排序后矩阵的最后一列作为变换结果。经过以上操作后，它能将原文中相似的上下文聚集在一起，使得变换后的信息局部相关性极强，非常利于再压缩。

## 1.4 Brotli 与 Zstandard
* **Brotli**：专为 Web 设计，结合了 LZ77、霍夫曼编码和二阶上下文建模。它内置了一个静态字典（包含常见的 HTML/JS 关键词），使得它在压缩短文本时远优于 GZIP。  
* **Zstandard**：采用有限状态熵编码。Zstd 可以提供极高的解压速度和可调节的压缩率，广泛用于实时文件系统的压缩。

# 矩阵与浮点压缩
## 2.1 稀疏矩阵压缩格式与优化
### 2.1.1 通用稀疏格式：CSR 与 DCSR
最基础的无损压缩格式是压缩稀疏行（CSR）。

* **CSR 结构**：它不存储零值，仅存储三个数组：values（非零值）、col\_indices（列索引）、row\_ptr（行偏移指针）。  
* **DCSR**：为了进一步压缩，DCSR 对列索引应用了 Delta 编码。由于稀疏矩阵中非零元素往往局部聚集，差值通常很小，可以仅用少量比特存储。

### 2.1.2 压缩线性代数（CLA）
CLA 既是一种存储格式，也是一种框架。它通过轻量级的、基于值的压缩技术（如字典编码、RLE）对矩阵进行编码，并设计了特殊的线代算子，以便其能够直接在压缩值上执行。  

## 2.2 浮点无损压缩
浮点值的尾数部分往往有极高的随机性，使得基于重复模式的压缩（如 LZ77）和基于预测的差分编码几乎失效。

### 2.2.1 ALP：自适应无损浮点压缩
* **机制**：ALP 首先尝试将浮点值乘以 $10^k$，检查其是否可以无损转换为整型。如果可以，就将难以压缩的浮点分布转换为了易于压缩的整型分布。  
* **两阶段编码**：对于转换后的整型，ALP 使用 FastLanes 库进行帧参考编码或 Delta 编码

对于无法简单转为整型的浮点值，ALP 会对这些值的每一位进行分析，将高位与低位分离，对高位部分使用字典编码，从而实现比 Zstd 更高的压缩率。

### 2.2.2 FPZIP
基于一种简单的 Lorenzo 预测器，并结合了一个专门处理浮点值表示的组件，常用于一维到三维浮点数组的压缩。

### 2.2.3 预处理
- **Shuffle / Bitshuffle**：预处理技术并不是压缩算法，而要和通用压缩算法结合以达到优于仅采用通用压缩算法的效果。Shuffle 按字节重排序列，例如将一个浮点数组 `[f1, f2, f3, ...]` 的字节 `[b11,b12,b13,b14, b21,b22,b23,b24, ...]` 重排为 `[b11,b21,b31,..., b12,b22,b32,..., ...]`。Bitshuffle 则在比特级进行类似操作。重排后相邻字节/比特更相似，从而极大地提高通用压缩器（如 LZ4, Zstd）的压缩效率。

# 神经压缩与生成式模型
## 3.1 DeepZip：基于 RNN 的序列预测
* **原理**：压缩的本质是预测。如果可以准确预测下一个字符出现的概率，算术编码就能用极少的比特表示它。DeepZip 采用 LSTM 来学习序列或文本的长期依赖关系。  
* **优势**：相比于 LZ77 有限的滑动窗口，LSTM 理论上可以记住无限长的历史信息。

## 3.2 VAEs：基于流的模型
- **原理**：变分自编码器主要用于图像压缩。通过一系列可逆的神经网络变换，将复杂的信息分布映射到一个简单的先验分布（如高斯分布）。由于变换可逆，因此可以实现无损压缩。
